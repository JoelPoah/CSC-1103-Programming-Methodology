ANALYSIS:

1. Loop vs recursion at -O0 and -O1: the loop is much faster.
   The loop only adds a number and moves to the next one. Recursion has to make
   10,000 function calls, and every call saves a return address and a stack frame
   on the stack, then removes it again on the way back. That extra work makes
   recursion about 55x slower than the loop on the Laptop and about 2.6x slower on the Pi.

2. -O0 to -O1: the loop gets faster, recursion barely changes.
   At -O0, the loop reads and writes i and total from memory every time. At -O1
   the compiler keeps them in CPU registers, which is much faster (1.70x Laptop,
   6.32x Pi). Recursion is still 10,000 real function calls at -O1, so the
   time is mostly the cost of the calls and stays about the same. The Laptop -O1
   recursion average (693,700 ns) is slower than -O0, but its runs varied a lot
   (531,700 to 940,700 ns), so this is most likely noise rather than -O1 being worse.

3. -O2 and -O3: both programs take almost no time.
   n = 10000 is fixed in the code, so at -O2 the compiler works out the answer
   before the program runs. The Laptop -O2 assembly contains 50005000 as a fixed
   number and never runs the loop or calls counter. The program only prints the
   answer, so the times measure nothing. -O3 gives no extra gain because there
   is no work left to remove.

4. These tiny numbers are limited by the timer, not the code.
   The Laptop timer counts in steps of 100 ns, so results show only 0 or 100 ns.
   The Pi timer counts in steps of about 18.5 ns, which is why its results
   are always 74 ns (4 steps) or 92-93 ns (5 steps).

5. Laptop vs Pi:
   The Laptop runs the loop about 4.4x faster than the Pi at -O0, because its CPU
   is faster. But the Pi runs recursion about 4.7x faster than the Laptop at -O0.
   A likely reason is that Windows x64 function calls are more expensive: each call
   must reserve extra stack space (32 bytes of "shadow space"), so 10,000 calls
   need much more stack memory, and Windows has to give the program new stack pages
   as it grows. ARM on the Pi uses smaller frames and stores the return address in
   a register. This has not been measured directly, so it is the likely cause,
   not a confirmed one.
