FINDINGS:
1. Compiler optimisation did not help Stage B. Average times ranged from 5.27 s to 6.11 s with no clear pattern: -O2 was the slowest, and -O3 was the same as -O0. Runs at the same level varied by up to 1.7 s, which is more than the differences between levels.
2. Stage B ran at the same speed as Stage A. At -O0, Stage B (structs passed by pointer) took 5.27 s and Stage A (static module variables) took 5.44 s. Both stages do the same work for each trade, and using a pointer only adds a few nanoseconds per trade, so the way the code is structured does not change the speed.
3. Both stages are slowed down by reading the CSV file, which uses fgets and sscanf, and the -O flags cannot make these faster. Background activity on the computer (OneDrive syncing, antivirus, and the CPU slowing down when hot) caused 1–2 s of variation, which hid any small differences. To get a real speed-up, we need a faster parser (Stage A+).
